# The route table as the design gives it (Appendix B of design/access.final.md), one row per line:
#   METHOD PATTERN CLASS SINCE ONLY
# CLASS is public, any, console, session, desk or scope:<name>. SINCE is 1 for a route that existed before
# the access model and 2 for one it adds or another design announced ("(new)" and "(rsv)" in the appendix).
# ONLY is server for the rows that exist only in the headless build (the vault design's Tier D routes:
# `vault.admin`) and all for the others. A row of ANY is `axum::routing::any`. HEAD uses its GET row.
#
# This file is written from the appendix, not from src/auth/routes.rs, and `routes::golden` compares the
# two exactly: a row changed there, a row added or a row missing fails until this file says the same, so a
# change of a route's scope is a change to two files that a reviewer sees. `session` rows are compared
# without their elevation flag (the appendix says "own rule, 4.7"; the table holds `elevate: false` for all).
#
# The differences from the appendix, decided on purpose and the only ones:
#   + the eleven routes the code gained since the design counted them (marked "added since the appendix"):
#       GET /api/update/status (system.read), POST /api/update/check (services.control: it makes OAIY ask
#       GitHub for a release, so a monitor's token must not do it), POST /api/update/agent-flushed
#       (agent.serve) (the updater) and POST /api/plugins/:id/trust (plugins.install), and seven of the
#       receptionist's transfers and messages: GET /api/messages/:id (calls.read), DELETE /api/messages/:id
#       (calls.write), GET /api/ring/preview (calls.read), GET /api/ring/active (calls.read),
#       POST /api/ring/active/:id/respond (calls.write), POST /api/ring/notices/:id/dismiss (calls.write) and
#       POST /api/voice/calls/:id/message (calls.write), each classified on purpose in src/auth/routes.rs;
#   ~ four rows the design reserved (since 2, "(rsv)": the routes were not built) and the code built since,
#       before the access model merged (marked "built since the appendix"): GET /api/messages and
#       GET /api/ring/settings, PATCH /api/messages/:id and PUT /api/ring/settings. Their since is 1 now, because
#       the routes exist and `legacy` mode keeps the guard they were built with;
#   ! three of those rows have a scope the design does not have (marked "scope changed since the appendix"):
#       the owner's transfer settings, GET and PUT /api/ring/settings, are `calls.settings` (an act scope, not
#       dangerous, held by the `owner` preset and the relay's admin tier alone), where the design has calls.read
#       and calls.write; and PATCH /api/messages/:id, with the three routes that act on a message or a ring
#       (DELETE /api/messages/:id, POST /api/ring/active/:id/respond, POST /api/ring/notices/:id/dismiss, which the
#       design does not have), is `calls.manage` (an act scope, not dangerous, held by the `owner` preset and the
#       relay's call-control tier), where the design has calls.write. The design's routes of `calls.write` are held
#       by the `agent` preset, which is the Agent page: a page that may be untrusted must not be able to turn
#       transfers on, name VIP numbers, silence the owner's phones, clear what callers left or decline the owner's
#       rings;
#   - GET /api/update, the updater design's reserved row: it was built as GET /api/update/status;
#   - control.project (the change level of POST /api/mcp) and every other /api/relay/* route the relay design
#     adds are not rows: no route exists for them yet.
