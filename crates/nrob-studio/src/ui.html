Models

Pick a file or folder and the studio reads its headers to work out what it is. Language models go to chat, image models to images, video models to videos. Parts such as projectors, adapters, encoders and tokenizers attach to the model that needs them.

Reads GGUF (LLMs, Qwen Image, vision projectors), safetensors (SDXL, Qwen Image, LTX 2.3/2.5, Sulphur, LoRA adapters, text encoders, VAEs), diffusers and EXL3/DeepSeek folders, and tokenizer.json. Pickled .bin/.pt files are refused because loading them can run code.

Memory

Choose where weights live for each kind of job. Keeping blocks on the GPU is fastest, keeping them in RAM costs one PCIe copy per block, and streaming from the SSD saves both kinds of memory. The output is identical either way; only speed and memory use change.

Language model memory

GPUs

Mixture-of-experts models keep their shared weights on the GPU, cache hot experts in VRAM and RAM, and read the rest from the SSD a token at a time.

Endpoints

The API other apps call. Each route maps a path and method to a service and the dialect it speaks: OpenAI, or nrob's job API for tools such as coder-cli.

Server

Web pages can reach this port too, so without an API key, browser requests are refused unless their origin is listed. Apps, scripts and SDKs outside a browser are unaffected.

Use 0.0.0.0 to serve your network, and set an API key when you do. Address changes apply the next time the studio starts.

Companion apps

Language model

WebGPU runs GGUF models on any Direct3D 12, Vulkan or Metal GPU: the quantized matmuls go to the GPU, everything else runs on the CPU, and weights past the limit stay in RAM. DeepSeek and EXL3 checkpoints need CUDA.
